## 2. 三层架构核心（A2A + Skills + MCP）

### 2.1 架构总览

```
┌───────────────────────────────────────────────┐
│            主控 Agent（A2A 编排）                │
│   任务分解 / 分发 / 并行调度 / 聚合 / 重试       │
└───────────────────────────────────────────────┘
        │                │              │
        ▼                ▼              ▼
   ┌─────────┐    ┌─────────┐    ┌─────────┐
   │ 子 Agent │    │ 子 Agent │    │ 子 Agent │   ← A2A 多智能体协作
   └────┬────┘    └────┬────┘    └────┬────┘
        │              │              │
   ┌────┴──────────────┴──────────────┴────┐
   │          Skills 层（业务动作）          │
   │   数据接入 / 指标计算 / 文书生成 / 合规审核 │
   └────┬──────────────┬──────────────┬────┘
        │              │              │
   ┌────┴──────────────┴──────────────┴────┐
   │          MCP 层（工具接入）              │
   │   数据源 / 合同知识 / 审核 / 导出 / 配置   │
   └───────────────────────────────────────┘
```

### 2.2 三层职责划分

| 层 | 职责 | 特点 |
|----|------|------|
| **主控 Agent（A2A）** | 任务分解、分发、并行调度、结果聚合、错误重试 | 编排中枢，掌控任务生命周期 |
| **Skills 层** | 稳定、重复、规则明确的业务动作 | 可复用业务步骤，不负责状态管理 |
| **MCP 层** | 外部数据源、模板、审核、导出的工具接入 | 标准接口，边界按能力域拆分 |

### 2.3 三层如何协作

```
主控 Agent 接收用户需求
  → 分解为子任务，分发给子 Agent
  → 子 Agent 调用 Skills（业务动作）
  → Skills 通过 MCP 获取外部工具能力（数据/模板/法规/导出）
  → 主控 Agent 聚合所有子 Agent 结果 → 返回用户
```

> **设计原则：** A2A 负责"怎么编排"，Skills 负责"做什么动作"，MCP 负责"接什么工具"。三者解耦，各自独立演进。

## 3. A2A 编排层设计

### 3.1 主控 Agent 职责

```python
class OrchestratorAgent:
    """主控 Agent - A2A 编排中枢"""

    def __init__(self):
        self.data_agent = DataAgent()          # 数据接入子 Agent
        self.generation_agent = GenerationAgent()  # 合同生成子 Agent
        self.compliance_agent = ComplianceAgent()  # 合规审核子 Agent
        self.doc_agent = DocumentAgent()       # V2: 文档处理子 Agent
        self.recommend_agent = RecommendAgent() # V2: 智能推荐子 Agent

    async def generate_contract(self, user_request: dict):
        # 1. 任务分解
        tasks = self.decompose_task(user_request)
        # 2. 并行执行数据接入（3 Skills）
        customer = await self.data_agent.get_customer_info(tasks['customer'])
        history = await self.data_agent.get_historical_contracts(tasks['type'])
        regs = await self.data_agent.get_regulations(tasks['type'])
        # 3. 合同生成
        draft = await self.generation_agent.generate(customer, history, regs, tasks['req'])
        # 4. 合规审核（并行 3 Skills）
        compliance = await self.compliance_agent.check(draft)
        # 5. 结果聚合
        return {'contract': draft, 'compliance': compliance, 'references': history}
```

### 3.2 V1 vs V2 编排

| 能力 | V1 | V2 | 说明 |
|------|:--:|:--:|------|
| 任务分解 / 分发 | ✅ | ✅ | 基础编排 |
| 并行执行 | ✅ | ✅ | asyncio.gather |
| 结果聚合 | ✅ | ✅ | 汇总子 Agent 结果 |
| 错误重试 | ✅ | ✅ | 失败自动重试 |

| 决策优化 | ❌ | ✅ | 基于历史数据优化任务分配 |

## 4. Skills 层设计

### 4.1 Skills 划分原则

- 按**能力域**拆，不按接口数量拆
- 每个 Skill 只做一件事并做好
- Skills 是可复用业务步骤，不负责状态管理

### 4.2 V1 Skills（约 9 个）

| 子 Agent | Skills |
|---------|--------|
| 数据接入 | get_customer_info / get_historical_contracts / get_regulations |
| 合同生成 | build_prompt / generate / format_content |
| 合规审核 | identify_risks / check_regulations / calculate_score |

### 4.3 V2 新增 Skills（约 8 个）

| 子 Agent | 新增 Skills |
|---------|-----------|
| 数据接入 | 查风险案例 / 查行业标准 |
| 合同生成 | 多轮对话生成 / 条款精细化 |
| 合规审核 | 深度法规匹配 / 自动修复建议 |
| 文档处理 | 生成 Word / 生成 PDF / 版本对比 / 附件包 |
| 智能推荐 | 相似案例 / 标准条款 / 风险预警 |

## 5. MCP 层设计

### 5.1 MCP 划分原则

- 按**能力域**拆，不按单个接口拆
- MCP 负责外部工具接入，供 Agent 调用
- 边界清晰，可独立演进

### 5.2 V1 MCP（3 个）

## 6. 子 Agent 详细设计

### 6.1 数据接入子 Agent

**职责：** 从各种数据源获取信息

```python
class DataAgent:
    """数据接入子 Agent"""

    async def get_customer_info(self, customer_name: str):
        """Skill 1: 查询客户信息（经数据源 MCP）"""
        return await data_mcp.query_customer(customer_name)

    async def get_historical_contracts(self, contract_type: str):
        """Skill 2: 查询历史合同（经数据源 MCP）"""
        return await data_mcp.query_similar_contracts(contract_type, limit=5)

    async def get_regulations(self, contract_type: str):
        """Skill 3: 查询法规（经数据源 MCP）"""
        return await data_mcp.query_regulations(contract_type)
```

### 6.2 合同生成子 Agent

**职责：** 使用大模型生成合同内容

```python
class GenerationAgent:
    """合同生成子 Agent"""

    async def generate(self, customer, history, regs, requirements):
        """调用大模型生成合同初稿（经合同知识 MCP 取模板）"""
        template = await knowledge_mcp.get_template(contract_type)
        prompt = self.build_prompt(template, customer, regs, requirements)
        draft = await self.claude.generate(prompt)
        return self.format_content(draft)
```

### 6.3 合规审核子 Agent

**职责：** 检查合同合规性和风险

```python
class ComplianceAgent:
    """合规审核子 Agent"""

    async def check(self, draft: str):
        risks = await self.identify_risks(draft)      # Skill 1
        reg_check = await self.check_regulations(draft)  # Skill 2（经合规审核 MCP）
        score = self.calculate_score(risks, reg_check)   # Skill 3
        return {'risks': risks, 'regulation': reg_check, 'score': score}
```

## 8. 完整流程示例

### 8.1 用户创建合同（V1）

```
用户输入参数
  → FastAPI 接收请求
  → 主控 Agent 接收任务
  → 数据接入子 Agent（并行 3 Skills，经数据源 MCP）约 5 秒
  → 合同生成子 Agent（经合同知识 MCP 取模板，调用大模型）约 2-4 分钟
  → 合规审核子 Agent（并行 3 Skills，经合规审核 MCP）约 10 秒
  → 主控 Agent 聚合 → 保存数据库 → 前端展示
```

**时间估算：** V1 约 2.5-4.5 分钟（5 秒 + 2-4 分钟 + 10 秒）

### 8.2 用户创建合同（V2）

```
V1 流程基础上，增加：
  → 文档处理子 Agent（Word/PDF 生成、版本对比）
  → 智能推荐子 Agent（相似案例、标准条款、风险预警）
  → 质量评估（生成后 AI 自评，低于阈值自动重新生成）
```

## 10. 关键性能设计

- **异步长任务：** 合同生成采用异步任务队列，前端轮询状态
- **并行执行：** 数据接入 / 合规审核阶段用 asyncio.gather 并行
- **缓存：** Redis 缓存高频查询（模板、法规）
- **限流：** 大模型调用限流，保护 API 配额
- **可追溯：** 每个任务记录主控 + 子 Agent + Skills 执行日志
